# AIGateway 国际化（zh-CN + en-US）Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 给 AIGateway 桌面应用增加中英双语支持，跟随系统语言自动选择，用户可在设置里手动切换。

**Architecture:**
- 前端用 `vue-i18n@9` 抽离所有中文字符串到 `src/i18n/locales/{zh-CN,en-US}.json`，启动时从 Rust 设置读取语言并应用。
- Rust 后端的用户可见错误改为返回结构化 `AppError { code, params }`，前端按 code 查 i18n key 渲染；后端只保留单一语言（错误码 + 内部英文 log）。
- 系统托盘菜单文案由前端通过新 `rebuild_tray_menu` 命令通知 Rust 重建，Rust 端维护一个小型菜单文案查找表（不引入全量 i18n）。
- 语言设置 `language: "auto" | "zh-CN" | "en-US"` 持久化在 `settings.json`，默认 `"auto"`。

**Tech Stack:**
- Frontend: Vue 3.5 + vue-i18n 9.x + Vite 6
- Backend: Rust + Tauri 2 + serde
- 无测试框架（项目现状），采用"写代码 → `npm run tauri dev` 跑通 → 双语切换肉眼验证 → commit"流程代替 TDD。

**Out of scope（明确不做）:**
- 日文及其它语言（仅 zh-CN/en-US）
- 日志页面中**用户业务数据**（如 model 名、URL、JSON body）不翻译
- Profile 名称、Provider 协议标识（`openai-chat` 等代码常量）不翻译
- 后端运行时日志（`eprintln!` / Rust 内部日志）不 i18n

## 命名约定

i18n key 用点分小写：`<scope>.<section>.<element>`
- `common.*` — 通用按钮、确认、提示（save / cancel / confirm / copySuccess）
- `app.*` — App.vue 级别（bootToast）
- `home.*` — 首页
- `settings.*` — 设置页（含统计图表）
- `profileEdit.*` — 编辑提供商页
- `tray.*` — 系统托盘（前端不直接使用，但保留同步副本便于审计）
- `errors.*` — Rust 错误码映射

Provider 标识（`openai-chat`、`anthropic-message`）保持原值不翻译；但其**展示标签**（如"OpenAI Chat Completions"）走 i18n。

- [ ] **Step 1.4: 创建 i18n 实例与系统语言检测**

Create `src/i18n/index.js`:
```javascript
import { createI18n } from 'vue-i18n'
import zhCN from './locales/zh-CN.json'
import enUS from './locales/en-US.json'

const SUPPORTED = ['zh-CN', 'en-US']
const FALLBACK = 'en-US'

export function detectSystemLocale() {
  const raw = (navigator.language || navigator.userLanguage || '').toLowerCase()
  if (raw.startsWith('zh')) return 'zh-CN'
  return FALLBACK
}

export function resolveLocale(setting) {
  if (setting === 'auto' || !setting) return detectSystemLocale()
  return SUPPORTED.includes(setting) ? setting : FALLBACK
}

export const i18n = createI18n({
  legacy: false,
  locale: FALLBACK,                 // 真正的 locale 由 main.js 在挂载前覆盖
  fallbackLocale: FALLBACK,
  messages: { 'zh-CN': zhCN, 'en-US': enUS },
  warnHtmlMessage: false
})

export function setLocale(lang) {
  i18n.global.locale.value = lang
  document.documentElement.lang = lang
}
```

            auto_start: false,
            log_enabled: false,
            http_proxy: None,
            language: "auto".to_string(),
        }
    }
}

  pagePayload.value = payload ?? null
}

provide('navigate', navigate)
provide('pagePayload', pagePayload)

function showBootToast(msg) {
  bootToast.value = msg
  clearTimeout(bootToastTimer)
  bootToastTimer = setTimeout(() => { bootToast.value = '' }, 5000)
}
function dismissBootToast() {
  clearTimeout(bootToastTimer)
  bootToast.value = ''
}

onMounted(async () => {
  navigate('gateway')

  try {
    const settings = await api.getSettings()
    const status = await api.getProxyStatus()
    if (settings.autoStart && status.status !== 'running') {
      await api.startProxy()
    }
  } catch (e) {
    const msg = typeof e === 'string' ? e : (e?.message || JSON.stringify(e))
    showBootToast(t('app.bootError', { msg }))
    console.error('Auto-start failed:', e)
  }
})
</script>

- [ ] **Step 9.1: 创建 error.rs**

Create `src-tauri/src/error.rs`:
```rust
use serde::Serialize;
use serde_json::Value;

/// 结构化错误，发送给前端用于 i18n 渲染。
/// code 形如 "request.failed" / "upstream.unauthorized"；前端按 code 查 i18n key。
#[derive(Debug, Clone, Serialize)]
pub struct AppError {
    pub code: String,
    #[serde(skip_serializing_if = "Option::is_none")]
    pub params: Option<Value>,
    /// 仅用于 dev/log 的英文 detail（前端不展示，DevTools 可见）
    #[serde(skip_serializing_if = "Option::is_none")]
    pub detail: Option<String>,
}

impl AppError {
    pub fn new(code: impl Into<String>) -> Self {
        Self { code: code.into(), params: None, detail: None }
    }

    pub fn with_params(mut self, params: Value) -> Self {
        self.params = Some(params);
        self
    }

    pub fn with_detail(mut self, detail: impl Into<String>) -> Self {
        self.detail = Some(detail.into());
        self
    }
}

impl From<reqwest::Error> for AppError {
    fn from(e: reqwest::Error) -> Self {
        AppError::new("network.requestFailed").with_detail(e.to_string())
    }
}

impl From<serde_json::Error> for AppError {
    fn from(e: serde_json::Error) -> Self {
        AppError::new("parse.jsonFailed").with_detail(e.to_string())
    }
}
```

```javascript
import { i18n } from './index'

/**
 * 把 Rust 返回的 AppError 翻译为本地化文案。
 * @param {unknown} err - invoke 抛出的对象，可能是 AppError、Error 或字符串
 * @returns {string} 已翻译的用户可见文案
 */
export function translateError(err) {
  const t = i18n.global.t

  // Tauri invoke 失败时常常抛出字符串
  if (typeof err === 'string') {
    return err
  }
  if (err && typeof err === 'object') {
    if (typeof err.code === 'string') {
      const key = `errors.${err.code}`
      const params = err.params || {}
      const translated = t(key, params)
      // 翻译失败时 vue-i18n 默认返回 key 本身
      if (translated !== key) return translated
      // 兜底
      return err.detail || err.code
    }
    if (err.message) return err.message
  }
  return t('errors.unknown', { status: '?' })
}
```

use std::collections::HashMap;

/// 托盘菜单文案。zh-CN 是默认；其它语言通过 `lookup` 获取。
/// 为避免给后端引入完整 i18n，托盘菜单保留一份轻量副本。
pub fn lookup(lang: &str, key: &str) -> String {
    let table = match lang {
        "en-US" => en_us_table(),
        _ => zh_cn_table(),
    };
    table.get(key).copied().unwrap_or(key).to_string()
}

## 风险与注意事项

1. **vue-i18n v9 vs v10**：Vue 3.5 兼容 v9 和 v10，本计划锁 v9 是因为 v10 的 composition API only 模式对某些情况有 breaking，v9 更稳。
2. **Linux 中文字体**：某些桌面环境（如最小化 Ubuntu）缺中文字体，需提示用户安装或在打包时考虑嵌入 fallback 字体（出 scope）。
3. **托盘菜单文案表与前端 i18n 重复维护**：tray.rs 的查找表和 `locales/*.json` 的 `tray.*` 区域是两份字符串。当前选择是接受这点重复——避免把整个 i18n 引擎搬进 Rust。如未来菜单字符串爆炸式增长，可考虑通过命令把整张表从前端推到 Rust（增加状态同步复杂度）。
4. **Provider 协议标签**：`providerType` 的 value（`openai-chat` 等）是稳定 code，**不要**改成 i18n key 当 value，否则切换语言会破坏 profile 数据。
5. **commit 顺序**：每个 Task 完成后立即 commit，禁止跨 Task 累积。若中途发现先前任务有漏抽字符串，新开补丁 commit（如 `fix(i18n): missed strings in X`），不要 amend 历史。
